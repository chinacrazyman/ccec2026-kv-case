# 运行说明

## 一、工程说明

本工程为“面向高并发 KV 系统的数据结构工程化教学案例”的配套代码工程，服务于 CCEC2026 第三届全国计算机教学案例大赛。工程围绕高并发 KV 系统中的四类典型问题展开：

1. CPU Cache 与内存访问局部性：解释为什么相同 `O(n²)` 复杂度下，真实运行时间可能相差数十倍。
2. HashMap 极端碰撞与 Hash DoS 防御：解释哈希表平均 `O(1)` 为什么会退化，以及 Java 8 红黑树化机制的工程价值。
3. HashMap、Hashtable 与 ConcurrentHashMap 并发写入对比：解释线程安全、锁粒度与并发扩展性之间的工程权衡。
4. Bloom Filter 海量数据判重：解释如何用可控误判率换取极大的空间节省。

工程定位不是单纯演示 API 用法，而是通过“实验冲突—原理解释—源码验证—架构权衡”的方式，帮助学生从数据结构知识走向工程系统能力。

## 四、IDEA 中导入工程

1. 打开 IntelliJ IDEA。
2. 选择 `File → Open`。
3. 打开工程根目录 `ccec2026-kv-case`。
4. 等待 IDEA 自动识别 `pom.xml`。
5. 如果右侧 Maven 面板没有自动加载，点击 `Reload All Maven Projects`。
6. 确认 `src/main/java` 被识别为 Sources Root。
7. 确认编码设置为 UTF-8。

编码设置路径：

```text
File → Settings → Editor → File Encodings
```

建议全部设置为：

```text
UTF-8
```

JMH 注解处理设置路径：

```text
File → Settings → Build, Execution, Deployment → Compiler → Annotation Processors
```

勾选：

```text
Enable annotation processing
```

## 六、运行方式一：直接运行单个案例

### 1. CPU Cache 与内存访问局部性实验

运行类：

```text
cn.edu.massz.ccec2026.module1_cache.CacheLineLiveDemo
```

预期现象：

- 按行优先遍历耗时较短。
- 按列优先遍历耗时明显更长。
- 两段代码时间复杂度均为 `O(n²)`，但真实运行性能差异明显。

建议截图保存路径：

```text
results/cache-line/cache_line_live_demo.png
```

---

### 2. HashMap 极端碰撞与 Hash DoS 防御实验

运行类：

```text
cn.edu.massz.ccec2026.module2_hash.HashDoSAttackDemo
```

预期现象：

- `"Aa"` 与 `"BB"` 的 `hashCode` 均为 2112。
- 可生成 65536 个哈希值完全一致的字符串。
- 传统链表 HashMap 耗时明显高于 Java 8 HashMap。
- Java 8 HashMap 通过红黑树化机制显著降低极端碰撞带来的性能退化。

建议截图保存路径：

```text
results/hash-dos/hash_dos_attack_result.png
```

---

### 3. HashMap、Hashtable 与 ConcurrentHashMap 并发写入实验

运行类：

```text
cn.edu.massz.ccec2026.module3_concurrency.ConcurrencyCrashTest
```

预期现象：

- 普通 HashMap 在多线程共享写入下可能出现数据丢失。
- Hashtable 与 ConcurrentHashMap 能保证本实验中的数据完整性。
- 实验重点不是证明某一容器在任意场景下绝对最快，而是帮助学生理解线程安全、锁粒度、实现复杂度与并发扩展性之间的工程权衡。

建议截图保存路径：

```text
results/concurrency/concurrency_map_result.png
```

---

### 4. Bloom Filter 海量数据判重实验

运行类：

```text
cn.edu.massz.ccec2026.module4_bloom.BloomFilterLimitDemo
```

建议 VM Options：

```text
-Xms1g -Xmx4g
```

设置路径：

```text
Run → Edit Configurations → BloomFilterLimitDemo → VM options
```

预期现象：

- 1000 万合法 ID 写入布隆过滤器。
- 理论内存约为 22.85 MB。
- 100 万非法 ID 请求中，仅有极少量被误判放行。
- 实际误判率接近设计误判率 0.01%。

建议截图保存路径：

```text
results/bloom-filter/bloom_filter_result.png
```

## 八、JMH 基准测试运行说明

课堂现场可使用 `CacheLineLiveDemo` 建立认知冲突；国赛材料、实验报告和专家追问建议使用 JMH 结果支撑。

### 方式一：IDEA Maven 面板打包

1. 打开 IDEA 右侧 Maven 面板。
2. 展开 `Lifecycle`。
3. 双击 `package`。
4. 等待出现 `BUILD SUCCESS`。
5. 在 Terminal 中运行：

```bash
java -jar target/ccec2026-kv-case-benchmarks.jar CacheLineJmhBenchmark
```

### 方式二：命令行打包

如果本机已安装 Maven，在工程根目录运行：

```bash
mvn clean package
java -jar target/ccec2026-kv-case-benchmarks.jar CacheLineJmhBenchmark
```

如果 PowerShell 提示无法识别 `mvn`，说明未安装 Maven 或环境变量未配置，可改用 IDEA 自带 Maven。

## 十一、常见问题处理

| 问题 | 可能原因 | 处理方法 |
|---|---|---|
| `mvn` 无法识别 | Maven 未安装或未配置环境变量 | 使用 IDEA Maven 面板，或安装 Maven |
| Guava 报红 | Maven 依赖未加载 | 点击 Maven 面板中的 Reload |
| JMH 找不到 benchmark | 注解处理未启用或未重新打包 | 开启 Annotation Processing，重新执行 package |
| BloomFilter 内存不足 | JVM 堆内存不足 | 添加 `-Xms1g -Xmx4g` |
| HashMap 并发实验结果不稳定 | 并发问题具有非确定性 | 多运行几次，记录典型结果 |
| 控制台中文乱码 | 编码设置不一致 | IDEA 与工程统一使用 UTF-8 |
| 运行速度过慢 | 数据规模较大 | 课堂演示可适当降低数据规模，正式截图使用稳定参数 |

## 十二、教学使用建议

本工程不是为了让学生记住某个运行数字，而是让学生通过实验理解：

1. 相同时间复杂度下，真实性能仍受硬件和内存访问模式影响。
2. 平均复杂度不代表极端输入下的安全性。
3. 线程安全不是简单加锁，而是同步粒度和扩展性的工程权衡。
4. 海量数据场景下，可以通过概率型数据结构换取空间节省。
5. 数据结构教学应从“会画结构图”走向“能解释系统设计”。
